## Лабораторная работа 1: Калькулятор метрик Холстеда (C++)

Интерактивный веб-калькулятор для расчёта метрик Холстеда по исходному коду программ на C++.

- **Демо:** [Lab1/](https://vbuyel.github.io/bsuir_Software_Standartization/Lab1/)
- **Исходный код:** [Lab1/](./Lab1/)

### Возможности
- Токенизация и лексический анализ исходного кода C++.
- Классификация уникальных операторов ($\eta_1$) и операндов ($\eta_2$).
- Расчёт базовых метрик: словарь ($\eta$), длина программы ($N$).
- Расчёт производных метрик: объём программы ($V$), сложность ($D$), трудоёмкость ($E$), время реализации ($T$) и прогнозируемое число ошибок ($B$).

### Правила классификации

#### Операторы ($\eta_1, N_1$)
- **Знаки операций и присваивания:** `=`, `+`, `-`, `*`, `/`, `%`, `++`, `--`, `&&`, `||`, `!`, `==`, `!=`, `<`, `>`, `<=`, `>=`, `+=`, `-=` и др.
- **Разделители и знаки препинания:** `;`, `,`, `.`, `->`, `::`, `<<`, `>>`, `:`
- **Парные скобки:** `( )`, `{ }`, `[ ]` (парные скобки учитываются по открывающей; скобки сразу после имени функции не дублируются).
- **Ключевые слова управления:** `for`, `while`, `switch`, `case`, `default`, `break`, `continue`, `return`, `goto` и др.
- **Составные операторы:** несколько служебных слов в составе единой конструкции считаются одним оператором:
  - `if...else` (условный оператор с веткой `else`; одиночный `if` без `else` учитывается как `if`);
  - `do...while` (цикл с постусловием `do` и закрывающим `while`);
  - `try...catch`.
- **Имена функций и подпрограмм:** пользовательские функции (`main`, `nextTerm`, `absValue`...), а также стандартные подпрограммы и потоки (`cout`, `cin`, `endl`...).

#### Операнды ($\eta_2, N_2$)
- **Типы данных:** `int`, `double`, `float`, `char`, `bool`, `void`, `long`, `short`, `unsigned`, `signed`, `string`, `size_t` и др.
- **Идентификаторы:** имена переменных, массивов и параметров функций (`x`, `y`, `vs`, `eps`, `n`, `mode`...).
- **Константы и литералы:**
  - Числовые литералы (`0`, `1`, `2`, `0.0001`, `100`...);
  - Строковые литералы (`"Enter x: "`, `"ready"`, `"done"`...);
  - Символьные литералы (`'a'`, `'\n'`...);
  - Литеральные константы (`true`, `false`, `nullptr`, `null`).

## Лабораторная работа 2: Парсер метрик Джилба (C++)

Веб-парсер с графическим интерфейсом для расчёта метрик логической сложности потока управления (метрики Джилба) по программе на C++.

- **Демо:** [Lab2/](https://vbuyel.github.io/bsuir_Software_Standartization/Lab2/)
- **Исходный код:** [Lab2/](./Lab2/)
- **Анализируемая программа:** [Lab2/sample.cpp](./Lab2/sample.cpp)

### Возможности
- Токенизация исходного кода C++ (комментарии и директивы препроцессора отбрасываются).
- Поиск операторов ветвления и циклов, расчёт глубины вложенности.
- Вывод на экран: абсолютная сложность $CL$, относительная сложность $cl$, максимальный уровень вложенности $CLI$.

### Правила учёта (метрика Джилба)

| Конструкция | Входит в $CL$ | Вложенность |
|---|---|---|
| `if`, `else if` | да | увеличивает глубину тела |
| `for`, `while`, `do` | да (`do…while` — один раз по `do`) | увеличивает глубину тела |
| `case` | да | альтернатива внутри `switch` (глубина = текущая) |
| `else`, `default` | нет (условия не проверяют) | `else` открывает ветку; `default` — нет |
| `switch` | нет (проверки — у `case`) | увеличивает глубину тела |

- Пример преподавателя: `for` и внутри него `if` → уровень вложенности **1**.
- Формулы методички вида «`CASE` с $n$ ветвями ≡ $n-1$ операторов `IF`, глубина $n-2$» верны для `switch` **с** `default` ($CL$ от `switch` = число меток `case` = $n-1$). Для `switch` **без** `default` считаются все `case`, shortcut-формулы $n-2$ / $2n-1$ не применяются.

$$
cl = \frac{CL}{N_{op}}
$$

где $N_{op}$ — общее число операторов программы (знаки операций, разделители, открывающие скобки пар, ключевые слова управления).

### Ручной расчёт для `sample.cpp`

В образце присутствуют: `while`, `for`, `do…while`, `if`/`else`, `switch` с `default` (внутри `if`), `switch` без `default` (внутри `while`), вложенность `for`→`if`.

Конструкции, дающие $CL$:

1. `while` (первый цикл)
2. `for`
3. `if` внутри `for` (глубина 1)
4. `do`
5. `if (mode > 0)`
6–7. два `case` в `switch` с `default` (глубина 2: внутри `if` и `switch`)
8. `while (t < 2)`
9–10. два `case` в `switch` без `default` (глубина 2)

Итого по черновику (совпадает с парсером):

| Метрика | Значение |
|---|---|
| $CL$ | $10$ |
| $N_{op}$ | $115$ |
| $cl$ | $10/115 \approx 0{,}087$ |
| $CLI$ | $2$ |

### Теория к защите: Джилб, Маккейб, граничные значения

Управление представляется ориентированным графом $G=(V,E)$ (блоки — вершины, переходы — дуги; блок-схемы по ГОСТ 19.701-90).

#### Метрика Маккейба (цикломатическая сложность)

$$
Z(G) = e - v + 2p
$$

- $e$ — число дуг, $v$ — число вершин, $p$ — число связных компонент (обычно $p=1$).
- Смысл: минимальное число линейно независимых путей (прогонов тестов), чтобы покрыть все ветви.
- Из чего состоит: только топология графа потока управления ($e$, $v$, $p$), без «насыщенности» условиями по тексту.

#### Метрика Джилба

Оценивает логическую сложность по насыщенности условными операторами:

- $CL$ — абсолютная сложность (число проверок условий);
- $cl$ — относительная ($CL$ к общему числу операторов);
- $CLI$ — максимальный уровень вложенности условий.

#### Метрика граничных значений

Граф делится по предикатным вершинам (исходящая степень $\ge 2$) и вершинам-приёмникам (исходящая степень $\le 1$). Для вершин считают скорректированные сложности:

- $S_a$ — абсолютная граничная сложность (сумма по вершинам);
- $S_o = 1 - \dfrac{v-1}{S_a}$ — относительная граничная сложность.

На защите достаточно уметь объяснить состав Маккейба ($e,v,p$) и Джилба ($CL, cl, CLI$) и по своему черновику/`sample.cpp` показать $CL$ и $CLI$ вручную.
